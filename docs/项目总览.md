# TDLauncher 项目总览

> Telegram 下载器的 Windows 桌面图形界面，为 [tdl](https://github.com/iyear/tdl)（Telegram 下载 CLI）提供可视化封装。
> 更新日期：2026-07-22

---

## 1. 项目目的

把 `tdl` 的命令行能力包装成一个**稳定、易用、可长期使用**的 Windows 本地下载工作台：

- 粘贴 Telegram 消息链接即可下载媒体，实时看到进度
- 支持帖子、私有频道、评论区、话题等多种链接
- 按频道自动归档、内容类型过滤、批量队列、代理、断点续传等
- 面向自建/自用场景，数据与操作都在本地

**定位**：Telegram 媒体下载工作流工具，而不是 `tdl dl -u` 的按钮封装。

## 2. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | Python 3.12 | 子进程管理稳定、GUI 生态成熟、便于打包 |
| GUI | PySide6（Qt 6） | 组件成熟，QSS 可做定制主题 |
| 子进程 | QProcess | 异步读取输出，不阻塞事件循环 |
| 下载引擎 | tdl（Go，外部二进制） | 吃满带宽、支持受保护频道、导出等 |
| 打包 | PyInstaller | 生成独立 exe |

> 早期有一个 PowerShell WinForms 原型，已冻结为「验证原型」，正式版用 Python 重写。

### 模块职责

| 模块 | 职责 |
|---|---|
| `main.py` | 入口：创建 QApplication、加载图标、启动主窗口 |
| `config.py` | `Config` dataclass；`load()` / `save()` 读写 `config.json` |
| `link_parser.py` | 解析链接为 `ParsedLink`（public_post / private_post / comment / thread / unknown） |
| `command_builder.py` | 把链接 + 配置拼成 `tdl` 参数列表（含评论区两步流程） |
| `tdl_runner.py` | 用 QProcess 启动 tdl，异步转发 stdout/stderr，停止时杀进程树 |
| `progress_parser.py` | 从 tdl 输出行提取百分比、速度、错误 |
| `main_window.py` | 全部界面与交互（本次重构重点） |

## 4. 数据流 / 控制流

### 一次下载

```
粘贴链接
  → _on_links_changed()      解析并在识别行提示
  → 点击「开始下载」
  → _start_download()        每个链接建一个 Job（含若干命令）
  → _pump() / _start_job()   逐条串行调度
  → _run_job_cmd()           启动 tdl 子进程
  → _on_job_output()         按帧分流输出
  → _process_job_frame()     进度帧喂 UI / 噪音丢弃 / 消息写日志
  → _on_job_cmd_exit()       命令结束，推进到下一个
```

### 评论区下载（三步）

```
① tdl dl -u <帖子>            下载帖子本身
② tdl chat export -c <频道> --reply <消息ID> -o tmp.json   导出评论列表
③ tdl dl -f tmp.json          下载评论区媒体
```

### 自动归档

逐条模式下，每条链接用独立目录：

```
{下载目录} / {频道显示名} / {消息ID} /
```

频道显示名通过 `tdl chat ls -o json` 解析并缓存；非法文件名字符会被清理。

### tdl 输出翻译

tdl 用 `\r` 原地刷新，约 30 帧/秒。程序按帧分流：

| 帧类型 | 处理 |
|---|---|
| 逐文件进度帧 | 只喂 UI（大数字 / 格量 / 逐文件列表 / 速度 / ETA），不写日志 |
| `CPU: … Memory: …` | 丢弃（噪音） |
| 其余消息（错误/状态/摘要、`done!`） | 写入可折叠日志；`done!` 标记子项完成 |

### 窗口缩放

设计画布固定 1280×720（16:9），窗口锁定同比例、最小 1280×720，放大到全屏。用 `QGraphicsView + 场景` 承载固定画布，`resizeEvent` 锁比例、`fitInView` 等比缩放。

## 5. 关键设计决策

1. **QProcess 而非 subprocess.Popen**：异步信号，避免下载时 GUI 卡死。
2. **tdl 进程必须串行**：tdl 的 session 是 bolt 数据库、带独占锁，多进程会报 `Current database is used by another process`。
3. **输出按帧分流**：进度只进 UI、噪音丢弃、真正消息进日志，日志始终很小。
4. **固定画布 + 等比缩放**：保证任何窗口尺寸下布局比例不变形。
5. **只改前端**：界面重构只动 `main_window.py`，后端五个模块未改。

### `main_window.py` 内部结构

| 类 / 区块 | 作用 |
|---|---|
| `TipLabel` | 带阴影的悬浮提示 |
| `CellsBar` | 进度格量化（24 格，仅更新变化格） |
| `QueueRow` | 队列一行（标记 + 名称 + 百分比 + 迷你进度条），可点击切换 |
| `FileRow` | 逐文件列表一行（名称 + 进度条 + 状态） |
| `Job` | 一个链接的下载任务（含命令、进度、文件、日志、状态） |

`MainWindow` 主要能力：
- `_build_ui` / `_apply_theme`：终端主题布局与样式
- `resizeEvent` / `_fit`：窗口等比缩放
- `_start_download` / `_pump` / `_start_job` / `_run_job_cmd`：逐条串行调度
- `_on_job_output` / `_process_job_frame` / `_apply_progress_frame` / `_job_feed_file`：tdl 输出翻译
- `_show_detail` / `_select_job` / `_ensure_detail_file`：队列选中与详情联动
- `_sanitize_folder_name` / `_resolve_channel_name`：归档命名
- `_apply_config` / `_save_config`：配置读写

## 8. 运行与打包

### 运行（源码）

```powershell
pip install -r requirements.txt
python app\main.py
```

### 打包（独立 exe）

```powershell
pip install pyinstaller
pyinstaller --noconsole --name TDLauncher --add-data "vendor/tdl.exe;vendor" app/main.py
```

> 仓库不含 `vendor/tdl.exe`；打包前需从 [tdl releases](https://github.com/iyear/tdl/releases) 下载放入 `vendor/`。Release 里可附含 tdl.exe 的便携包。

## 9. 已知限制

- **tdl 进程串行**：受 session 独占锁限制，链接与链接之间只能一条一条来；`-l`（并发数）只在单条链接内部对多个媒体条目生效。
- **逐文件列表显示的是「下载描述符」而非文件名**：tdl 进度行只给「频道(id):消息ID」，拿不到真实文件名；评论区子项更是只有消息 ID。
- **进度为估算**：tdl 不逐条报完成（只有子项级的 `done!`），整体完成度靠命令退出码判断。
- **速度受代理/账号限制**：GUI 只负责更好调用 tdl，不承诺提速。
